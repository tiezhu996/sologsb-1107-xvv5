# 手工造纸帘纹与工序档案

围绕手工造纸的纸帘、纤维料批、抄纸工序与成纸样本建立一体化档案。界面可登记纸帘丝径与帘纹间距、推算网目密度，跟踪料批打浆度，复测抄纸帘纹偏差，并按匀度与帘纹条数复核样本。所有业务数据保存在浏览器 IndexedDB 中，无需后端服务。

## Docker 一键启动

```bash
cp .env.example .env && docker compose up -d --build
```

默认映射端口为 `21807`。启动后访问 `http://localhost:21807`。

## 数据存储说明

数据存储使用 IndexedDB，Dexie 数据库名为 `gbpapermill-db`。

- `version(1)`：建立 `moulds`、`fiberBatches`、`sheetRuns`、`paperSamples` 四张表及编号、日期、状态等索引。
- `version(1)`：建立 `moulds`、`fiberBatches`、`sheetRuns`、`paperSamples` 四张表及编号、日期、状态等索引。
- `version(2)`：为四张表加入 `schemaRev` 索引，并通过 `upgrade` 将存量记录回填为版本 `2`。
- `version(3)`：纸帘规格版本化并新增 `repairOrders` 返修单表。
  - 纸帘台帐仅保留“当前规格”（`specRev` 从 1 起，每应用一张返修单 +1）。
  - 抄纸工序在登记时锁定当时的丝径、帘纹间距与密度快照（`specRev/specWireDiameter/specStripeGap/specMeshDensity`），偏差始终按锁定版本判定，纸帘返修不改判旧工序。
  - 成纸样本锁定对应工序的规格版本（`specRev`），并带 `rechecked/archived` 复检与归档状态。
  - 升级时旧纸帘回填为 v1 初始规格，旧工序按当时规格补快照，旧样本视为已复检归档——**旧数据升级后仍可完整读完**。
- 数据库首次创建时通过 `populate` 写入 5 张纸帘、5 个纤维料批、8 槽抄纸工序、6 个成纸样本与 3 张返修单（已应用 / 待应用 / 失败可重试各一）。
- 页面顶部的“导出 JSON”可下载五张表的完整备份，并为每条工序、样本附 `specBasis` 文字说明其依据的版本。

## 纸帘返修与规格版本规则

纸帘返修后可能更换丝径或帘纹间距，系统按以下规则保证“旧工序按当时规格判定、新工序才用返修后规格”：

1. **可核对的返修单**：在纸帘台帐“登记返修单”，写清返修原因、原规格快照与拟改规格（丝径、间距、推算密度），单号唯一；登记后纸帘置“待修补”，台帐当前规格不变。
2. **应用前标出待复检样本**：登记返修单时，该纸帘关联工序下尚未复检的成纸样本会被标为“未复检”并移到“待复检区”；在成纸样本页复检通过后才能归档。
3. **应用走事务**：点击“应用规格”后拟改规格成为纸帘当前规格，版本号 +1；此前的工序与样本继续锁定各自版本。写入失败时事务整体回滚，原数据保留，返修单标“失败”并可“重试应用”。
4. **工作台与导出**：工作台列出每条工序依据的规格版本（返修前的旧工序明确标注“旧版”）；JSON 导出同样逐条注明依据版本与复检/归档状态。

## 核心功能与路由表

| 路由 | 页面标题 | 核心功能 |
| --- | --- | --- |
| `/` | 工作台 | 查看纸帘状态分布、本周工序数、待复检样本与标准工序路径 |
| `/moulds` | 纸帘台帐 | 筛选纸帘，登记新纸帘，实时推算网目密度并登记/应用返修单（规格版本化） |
| `/fibers` | 纤维料批台账 | 按原料和打浆度筛选、比较，展开查看关联抄纸工序 |
| `/runs` | 抄纸工序记录台 | 按日期和帘号筛选，登记工序并即时按锁定版本判定 ±0.2 mm 帘纹偏差 |
| `/samples` | 成纸样本与透光检验卡 | 按匀度与帘纹条数分档，复检通过后归档，查看透光帘纹预览 |

未匹配的地址会回到工作台。
